# Author a Deck

The [manuscript directory](manuscript/README.md) contains slide YAML and the
descriptive paper. Edit the YAML for changes to a slide and the ordered Markdown
for changes to the paper.

- Set the flagship subject and theme under `project_config.deck` in
  [config.yaml](manuscript/config.yaml). For a second subject, add a
  `subjects.<subject>.content_prefix` entry and supply that prefix's
  `_short.yaml`, `_medium.yaml`, and `_long.yaml` files. The example
  configuration shows the theme fields.
- Use `title`, `section`, `content`, `stat`, `quote`, or `diagram` as a
  slide's `kind`. Follow the shipped YAML files for the fields each kind uses.
  Move long reference lists to speaker notes and link the full source on the
  slide to keep the footer and QR code clear.
- Reference facts with the `{{TOKEN}}` values generated by
  `src/deck_tokens.py`. The pinned reference supplies subject metadata,
  publication status, and the generated coverage report. The standalone
  project's own configuration supplies the deck's citation identity.
- Attach `source` to each fact-bearing slide. A relative path is resolved in
  the shared Template checkout and linked using `source_base_url`. The deck's
  own source-file URLs are checked against the standalone checkout.
- Use `slides_base_url` for QR links to the published slide pages. Local
  Markdown slide pages exist as soon as the decks are generated. A QR link
  reaches a specific build once those pages are available at the configured
  URL. Use a versioned URL when distributing a particular release.

Run [Build and Verify](build.md) after editing. Missing tokens, cliché matches,
and missing fact citations fail the slide build before deck files are written.
